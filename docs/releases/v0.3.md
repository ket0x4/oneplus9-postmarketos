## What's new since v0.2

The kernel series is 167 patches on Linux 7.3 (v0.2 had 148), and one kernel image now boots both
phones.

### The OnePlus 9 works

The OnePlus 9 (`lemonade`) is no longer a second-hand entry in the docs: it boots, runs Phosh and
does its hardware on the same image as the 9 Pro.

- **Both device trees in one image (patch 0149).** The kernel carries the 9 and the 9 Pro's trees
  and picks one from the project number the bootloader reports. Nothing per-phone is compiled in:
  Wi-Fi and Bluetooth take their addresses from the modem at boot, as before.
- **Panel:** the 1080x2400 Samsung AMB655X at 60 and 120 Hz, with the sunlight high-brightness mode
  (patches 0158, 0161).
- **Touch:** the Samsung S6SY792, which speaks the same protocol as the S6SY761 this driver already
  had, plus the optional reset line and the report-rate setting (patches 0151, 0156, 0165).
- **Cameras:** Sony IMX689 on the main camera (0159), all four sensors and their focus motors wired
  up (0160), CCI reset on runtime resume (0162), a CAMSS streaming unwind fix (0163) and the
  ultrawide's AK7375C (0164).
- **Shared board parts (0157):** speakers, codec, call audio, haptics, flash, charging and USB-C now
  live in `sm8350-oneplus-common.dtsi` instead of being copied per board.

### USB-C docks and DisplayPort

Two display fixes, both of which matter on a dock rather than a plain adapter:

- `typec_ucsi` no longer resets the shared QMP combo PHY mux back to USB3-only while a partner
  reports an alternate mode (patch 0166). That was the 2-second DP→USB flap and the
  `disp_cc_mdss_dp_link_clk ... -EBUSY` in the log.
- `msm_dp` stops re-probing AUX on every detect, resets AUX on an out-of-band AltMode timeout, and
  releases the PHY if the link clock fails (0167).

### Fixes

- **Haptics:** the top speaker's amplifier is reserved per board, so the earpiece profile doesn't
  fight the speakers.
- **Scheduler:** energy-aware scheduling is off by default; it made scrolling worse on the 9.
- **Quick settings:** the touch-rate toggle finds the S6SY792 as well as the S3908, and the sunlight
  helper copes with a `monitor-sensor` that has no `stdbuf`.

### Under the hood

- The kernel build embeds both device trees and CI checks the patch series on every change.
- New `checks.yml` CI job: shell/Python syntax, shellcheck, `udevadm verify` on the rules, a real
  `git apply --check` of every pmaports patch against its pinned upstream, unit `ExecStart`
  targets, and doc links.
- Fetched tarballs (busybox, FFmpeg, the phosh source) now have pinned checksums.
- `.gitattributes` keeps patches and scripts byte-exact on checkout, which the kernel build's patch
  hash depends on.

### Upgrading from v0.2

Install the new `Image`, modules and `initramfs.gz` as usual — the boot image is packed from your
own `vendor_boot.img` with `scripts/op9-boot-image.sh`, unchanged. Then, from a checkout of this tag:

```sh
sudo cp -a rootfs/. /
sudo udevadm control --reload && sudo udevadm trigger
sudo systemctl enable --now usb-gadget-ensure
```

The phone user needs the `video` group on postmarketOS too, for the quick settings' sysfs writes:

```sh
sudo addgroup user video    # or `usermod -aG video <user>`
```

Rebuild `postmarketos/pmaports/community/phoc`, `.../wlroots` and
`.../phosh-op9-quick-settings`, since this series moves them to Phoc 0.59 and adds the second
panel's name to the touch driver.
